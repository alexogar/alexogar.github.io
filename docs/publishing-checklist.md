# Publishing and indexing checklist

The repository already contains an Astro static site, canonical metadata, a Person schema.org profile, an autogenerated sitemap and a `robots.txt` allowing indexing. Search discovery is not guaranteed simply by committing code.

## GitHub Pages

1. Merge the site PR only after the publication review and green CI checks.
2. Open **GitHub → alexogar/alexogar.github.io → Settings → Pages**.
3. Confirm **Build and deployment → Source: GitHub Actions**. The workflow `.github/workflows/site.yml` expects this mode, not branch-based/Jekyll publishing.
4. Open **Actions → Verify and deploy site**. Confirm the `verify` and `deploy` jobs passed on `master` and the `github-pages` environment has a successful deployment. If there are failures, inspect logs instead of assuming deployment happened.
5. Open `https://alexogar.github.io/`, `/cv/`, `/work/autobahn-platform/`, `/work/plexus-interop/`, `/work/lorely/`, `/robots.txt` and `/sitemap-index.xml`. Verify HTTP 200, HTTPS, content and canonical URLs. The older site may remain until Pages is correctly configured.
6. Confirm the PDF download and meta social preview image load correctly.

## Search engines

1. In [Google Search Console](https://search.google.com/search-console), add the URL-prefix property `https://alexogar.github.io/` and follow its verification steps.
2. Submit sitemap: `https://alexogar.github.io/sitemap-index.xml`.
3. Use **URL Inspection → Request indexing** for the home page and case studies after deployment. This requests crawling; it does not promise a ranking.
4. Add the site to [Bing Webmaster Tools](https://www.bing.com/webmasters/) and submit the same sitemap.
5. Set the site URL in the GitHub profile website field (in addition to the README), LinkedIn Contact info and LinkedIn Featured section.
6. After search engines recrawl, compare results for "Alexey Ogarkov", "Alexey Ogarkov Principal Engineer" and "Алексей Огарков". Country and personalization change ordering.
7. Recheck deployment and index coverage later instead of relying only on `site:` searches.

## External profiles

- LinkedIn: update headline, About, Experience and Featured manually using the companion copy from this change.
- GitHub: keep README focused on outcomes, and pin repositories that show relevant engineering credibility.
- Public talk references: add permanent source links when validated; do not link to broken archival pages.

## Known verification limits

This review cannot directly verify your GitHub Pages account settings, Google Search Console ownership, or LinkedIn edit permissions. A browser error from a third-party fetcher is not conclusive proof that a site is offline. Test from a regular browser as part of launch.
